# Doxvelt v0.2.0-alpha.2 desktop alpha

**Export / import** now transfers a complete workspace: authored collection,
pinned content, accepted stories and alternate paths, fictional dates, player
scene headings, publication history and exact Reverie memories. Export writes a
folder containing `workspace.json` and `source/`; keep that folder together.
Review the archive before restoring into a new folder, then open the restored
folder as a DSH workspace. Existing destination folders are never replaced.

Transfer validates history, subjective character source and native memories,
stages the complete restore, and publishes it atomically without model calls or
reforming memories. Interrupted work can be retried; a completed restore remains
recognizable after restart. Indexed history validation and reused publication
sources keep long-story transfers responsive, with cancellation checks during
validation and staged insertion.

## Player package

Download `doxvelt-v0.2.0-alpha.2-windows-x64.zip` and its `.zip.sha256` file from
this release. Verify the ZIP digest, extract the complete folder, fully quit DSH,
and run `install.ps1` as described in [README](../../README.md). Installation
uses a verified, versioned user-local copy. Stories and memories remain in their
workspace, and model credentials remain in DSH. Back up the workspace before
upgrading an alpha.

GitHub's automatic source archives are developer downloads.

## Verification and limits

The packaged verifier exercises isolated installation/reinstallation, damaged
update rejection, source authoring, manual/model play, memory formation/recall,
archive export/review/import, host restart, safe retry and identical re-export.
Transfer makes no additional model calls. The actual DSH desktop browser harness
also exercises the extracted plugin's archive controls and multiple viewports.
These checks use disposable workspaces and scripted providers, not real stories
or paid model calls.

Rust tests and Linux CI cover the maintained engine. Windows retains the known
SQLite cleanup-lock and timing failures in the retired TypeScript reference
suite; a green Linux run does not establish a fully green Windows reference run.
Detailed commands and package verification are in [CONTRIBUTING](../../CONTRIBUTING.md).

Credentials, DSH chats, unaccepted drafts and installation-local navigation are
excluded. Combined archives have the size and file limits described in the
[workspace guide](../WORKSPACES.md). Older single-simulation packages retain their
compatibility format. Legacy Pi ZIP migration remains deferred. Other platforms
require source builds; live model quality and assistive-technology behavior are
not established by the scripted checks.

The existing follow-ups in issues #51–#55 remain separate from this release.
Inspect legacy model files and compiled content before sharing older simulation
packages until the redaction follow-up is resolved.
